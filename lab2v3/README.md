# Лабораторна робота №2

### **Тема:** Клас із кількома конструкторами. Життєвий цикл об’єкта.

### Варіант: 3 — Клас Student

* **Поля:** `_name` (string), `_studentId` (string), `_averageMark` (double).
* **Властивості:** Name, StudentId, AverageMark.
* **Конструктори:** конструктор за замовчуванням, параметризований конструктор (name, studentId, averageMark), ланцюговий виклик конструкторів через `: this()`.
* **Методи:** `GetStudentCard()` для отримання інформації про студента.
* **Валідація:** середня оцінка повинна знаходитися в межах від 0 до 100.

# **Хід роботи:**

### Було встановлене середовище розробки VS Code з усіма необхідними розширеннями: C# Dev Kit; .NET Install Tool.

### Було створено консольний проєкт `lab2v3` у директорії `OOP-Vasilevich`. Відповідно до варіанту створив клас **Student**.

Клас містить: **Приватні поля:** ім’я студента, ідентифікатор студента та середню оцінку.

**Публічні властивості для доступу до полів:** `Name`, `StudentId` та `AverageMark`. Для властивості `AverageMark` передбачена перевірка значення, яке повинно знаходитися в межах від 0 до 100.

**Перевантажені конструктори:** один конструктор створює студента зі стандартними значеннями, а другий приймає ім’я, ідентифікатор та середню оцінку. Для уникнення дублювання коду використовується ланцюговий виклик конструктора через `: this()`.

**Методи:** `GetStudentCard()`, який повертає інформацію про студента.

**Метод, що виконує дію, пов’язану з класом.** Створив клас **Program**. У методі **Main()** було створено 3 об’єкти класу **Student**. Для об’єктів було викликано метод **GetStudentCard()** та використано **Console.WriteLine** для виведення результатів роботи програми.

Для перевірки валідації було виконано спробу встановити середню оцінку, яка виходить за допустимий діапазон, після чого програма вивела повідомлення про помилку.

Для демонстрації роботи життєвого циклу об’єктів та фіналізатора було створено тимчасові об’єкти. Для примусового запуску збирача сміття використано **GC.Collect()** та **GC.WaitForPendingFinalizers()**.

У класі **Student** також було реалізовано деструктор (фіналізатор), який демонструє завершення життєвого циклу об’єкта.
## Висновок.
У ході роботи я реалізував клас Student з двома перевантаженими конструкторами та ланцюговим викликом : this(), що дозволило уникнути дублювання коду ініціалізації. Я дослідив життєвий цикл об'єкта: оператор new виділяє пам'ять у купі та викликає конструктор; об'єкт існує, доки на нього є посилання; після втрати посилань збирач сміття позначає його як придатний до видалення, і перед звільненням пам'яті викликається деструктор (фіналізатор). Тимчасові об'єкти, створені в окремому методі, були знищені після GC.Collect() і GC.WaitForPendingFinalizers(), що підтвердили повідомлення деструкторів. Момент виклику фіналізатора недетермінований, а примусовий запуск GC доречний лише в навчальних цілях.
