# Лабораторна робота №18, варіант 3: Обробка файлів

**Тема:** Власні винятки та патерн Result.  
**Проєкт:** `lab18v3` — консольний застосунок .NET 10.

## Мета

Створити власний тип винятку для помилки формату файла та застосувати `Result<T>` для повернення очікуваних помилок запису без кидання винятків.

## Сутності та реалізація

- `InvalidFileFormatException` успадковується від `Exception` і зберігає ім'я файла та очікуваний формат. Реалізовано конструктори з повідомленням і з внутрішнім винятком.
- `Result<T>` має властивості `IsSuccess`, `Value`, `Error` і фабричні методи `Success`, `Failure(string)` та `Failure(Exception)`.
- `FileProcessorService.ReadFile(path)` приймає файли формату `.txt`, а для іншого розширення викидає `InvalidFileFormatException`.
- `FileProcessorService.WriteToFile(path, content)` повертає `Result<bool>`: успіх при записі або повідомлення про помилку вводу/виводу чи невалідний шлях.
- `sample.txt` містить демонстраційні дані й копіюється до каталогу запуску.

## Демонстрація

У `Main` читається коректний файл, обробляється власний виняток для `.csv`, а також показані успішний запис і відхилення порожнього шляху через `Result<bool>`.

## Контрольні питання

1. **Навіщо створювати власні типи винятків?**  
   Вони точно описують помилки конкретної предметної області. Код, що викликає метод, може перехопити саме цей тип і отримати додаткові дані, наприклад ім'я файла й очікуваний формат.

2. **Які конструктори рекомендується реалізовувати для власних винятків?**  
   Зазвичай додають конструктор без параметрів, з повідомленням і з повідомленням та внутрішнім винятком. У цьому прикладі є конструктори з даними помилки та з внутрішнім винятком, а базовий конструктор формує повідомлення.

3. **Що таке патерн Result і коли він кращий за винятки?**  
   `Result<T>` містить або значення успішної операції, або опис помилки. Він доречний для очікуваних невдач, які є звичайною частиною роботи програми; винятки краще залишити для помилкових чи непередбачених станів.

4. **Які сценарії краще обробляти через винятки, а які — через `Result<T>`?**  
   Винятки підходять для неочікуваних помилок, як-от неправильний формат, що перешкоджає читанню. `Result<T>` зручний для передбачуваних відмов — наприклад, невалідного шляху або відсутності прав на запис, коли викликач має перевірити статус і показати пояснення.
