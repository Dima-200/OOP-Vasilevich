# Лабораторна робота №17, варіант 3: Отримання списку замовлень

**Тема:** Обробка IO/мережевих помилок та патерн Retry.  
**Проєкт:** `lab17v3` — консольний застосунок .NET 10.

## Мета

Навчитися обробляти тимчасові помилки вводу/виводу та мережевих запитів, застосовувати `try-catch` і реалізовувати повторні спроби з експоненційною затримкою.

## Реалізація

- `FileProcessor.GetLines(path)` імітує дві невдалі спроби з `IOException`, після чого повертає список ідентифікаторів замовлень.
- `NetworkClient.GetApiResponse(endpoint)` імітує чотири невдалі спроби з `HttpRequestException`, після чого повертає успішну відповідь API.
- Узагальнений `RetryHelper.ExecuteWithRetry<T>` приймає операцію, ліміт повторів, початкову затримку та необов'язковий `shouldRetry`. Кожна спроба й причина помилки виводяться в консоль.
- Затримка перед повтором обчислюється як `initialDelay × 2^(номер повтору − 1)`. Для демонстрації задано коротку початкову затримку 25 мс.
- Окремий приклад показує, що `InvalidDataException` не повторюється, бо предикат дозволяє повтор лише для `IOException` та `HttpRequestException`.

## Запуск

З каталогу `lab17v3` виконайте:

```bash
dotnet run
```

## Контрольні запитання

1. **Які винятки найчастіше виникають під час роботи з файлами та мережею?**  
   Для файлів це `IOException`, `FileNotFoundException` і `DirectoryNotFoundException`. Для мережевих запитів часто трапляються `HttpRequestException` і `SocketException`.

2. **Як працює патерн Retry і коли його застосовують?**  
   Retry повторює операцію після тимчасової помилки до успіху або вичерпання ліміту. Його застосовують для операцій, які можуть відмовити тимчасово, наприклад через короткий збій мережі чи зайнятий файл. Повторювати незмінювані помилки без сенсу.

3. **Як реалізувати експоненційну затримку?**  
   Після кожної невдалої спроби початкову затримку множать на степінь двійки: `delay = initialDelay × 2^(retryAttempt)`. Тому кожна наступна пауза довша за попередню.

4. **Для чого потрібен делегат `shouldRetry`?**  
   Він перевіряє тип винятку й вирішує, чи має сенс повторювати операцію. У цій роботі дозволено повтори для `IOException` та `HttpRequestException`; інші винятки одразу передаються виклику.

## Висновок

Реалізовано повторне читання замовлень із локального джерела та повторний запит до API після тимчасових помилок. Експоненційна затримка зменшує частоту повторних запитів під час збоїв, а `shouldRetry` не дозволяє повторювати операції для помилок, які не є тимчасовими.
