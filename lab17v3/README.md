# Лабораторна робота №17

## Тема
Обробка IO/мережевих помилок та патерн Retry.

## Варіант
3 — API-запит.

## Мета роботи
Навчитися обробляти помилки введення-виведення та мережеві помилки за допомогою механізму `try-catch-finally`, а також реалізувати універсальний механізм повторних спроб виконання операцій із використанням патерну Retry та експоненційної затримки.

## Виконання роботи

У ході лабораторної роботи було створено консольний застосунок мовою C#.

Реалізовано такі класи:

- **FileProcessor** — імітує читання файлу. Перші дві спроби завершуються помилкою `IOException`, третя — успішно.
- **NetworkClient** — імітує запит до API. Перші чотири спроби завершуються помилкою `HttpRequestException`, п'ята — успішно.
- **RetryHelper** — універсальний клас для повторного виконання операцій. Використовує узагальнений метод `ExecuteWithRetry<T>`, делегат `Func<T>` та параметр `shouldRetry` для перевірки можливості повторної спроби.

### Експоненційна затримка

Для кожної наступної повторної спроби час очікування збільшується вдвічі:

- 1-ша повторна спроба — 200 мс;
- 2-га повторна спроба — 400 мс;
- 3-тя повторна спроба — 800 мс;
- 4-та повторна спроба — 1600 мс.

## Відповіді на контрольні запитання

**1. Які типи винятків найчастіше виникають при роботі з файлами та мережею?**

Під час роботи з файлами можуть виникати `IOException`, `FileNotFoundException`, `UnauthorizedAccessException`. Під час мережевих операцій часто виникає `HttpRequestException`, а також інші помилки підключення та тайм-ауту.

**2. У чому полягає принцип Retry і коли його доцільно застосовувати?**

Retry — це патерн повторного виконання операції після тимчасової помилки. Його доцільно застосовувати під час мережевих запитів, роботи з файлами або зовнішніми сервісами, коли помилка може зникнути після певного часу.

**3. Як реалізувати експоненційну затримку між спробами?**

Час затримки збільшується вдвічі після кожної невдалої спроби. Для цього використовується формула `initialDelay * 2^(retryAttempt - 1)`.

**4. Для чого потрібен параметр shouldRetry?**

Параметр `shouldRetry` визначає, чи потрібно повторювати операцію після виникнення винятку. Це дозволяє повторювати лише ті помилки, які можуть бути тимчасовими, та не повторювати операції для помилок, які не можна виправити повторною спробою.

## Висновок

Під час лабораторної роботи було реалізовано універсальний механізм повторних спроб виконання операцій із використанням патерну Retry. Було перевірено обробку помилок читання файлів і мережевих запитів, а також роботу експоненційної затримки та фільтрації винятків через `shouldRetry`. Експоненційна затримка допомагає зменшити навантаження на систему під час тимчасових збоїв.
