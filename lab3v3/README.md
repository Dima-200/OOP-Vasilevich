# Лабораторна робота №3

### **Тема:** Керування ресурсами. Інтерфейс IDisposable. Життєвий цикл об'єкта.

### Варіант: 3 — Клас NetworkStream

* **Поля:** `_address` (string), `_isStreamOpen` (bool).
* **Властивості:** Address, IsStreamOpen.
* **Конструктор:** параметризований конструктор, який приймає адресу мережевого потоку.
* **Методи:** `Send(string data)`, `Dispose()`, захищений метод `Dispose(bool disposing)`.
* **Додатково:** деструктор та реалізація інтерфейсу `IDisposable`.

# **Хід роботи:**

### Було встановлене середовище розробки VS Code з усіма необхідними розширеннями: C# Dev Kit; .NET Install Tool.

### Було створено консольний проєкт `lab3v3` у директорії `OOP-Vasilevich`. Відповідно до варіанту створив клас **NetworkStream**.

Клас містить: **Приватні поля:** адресу мережевого потоку та ознаку його відкритого стану.

**Публічні властивості для доступу до полів:** `Address` та `IsStreamOpen`.

**Конструктор:** параметризований конструктор, який приймає адресу мережевого потоку та встановлює початковий стан потоку як відкритий.

**Методи:** `Send(string data)` для імітації відправлення даних через мережевий потік, `Dispose()` для звільнення ресурсу та захищений метод `Dispose(bool disposing)` для реалізації патерну звільнення ресурсів.

**Інтерфейс:** клас **NetworkStream** реалізує інтерфейс `IDisposable`, що дозволяє явно звільняти ресурси.

**Деструктор:** у класі реалізовано деструктор, який викликає `Dispose(false)` та демонструє автоматичне завершення роботи з ресурсом під час фіналізації об'єкта.

Створив клас **Program**. У методі **Main()** було продемонстровано три способи керування ресурсом.

Перший спосіб — використання **using**. Об'єкт створюється всередині блоку `using`. Після виходу з блоку метод `Dispose()` викликається автоматично, тому мережевий потік закривається.

Другий спосіб — **явний виклик Dispose()**. Об'єкт створюється звичайним способом, після чого викликається `stream2.Dispose()`. Це забезпечує явне звільнення ресурсу.

Третій спосіб — створення об'єкта без явного виклику `Dispose()`. Після втрати посилання на об'єкт використовуються **GC.Collect()** та **GC.WaitForPendingFinalizers()**. У результаті Garbage Collector запускає деструктор, який закриває мережевий потік.

Для запобігання повторному виклику фіналізатора після явного звільнення ресурсу використовується **GC.SuppressFinalize(this)**.

Таким чином, було продемонстровано використання `using`, явного `Dispose()` та автоматичної фіналізації об'єкта Garbage Collector.
